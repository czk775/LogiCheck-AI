# LogiCheck AI - 固定人工验收与演示单证包 (v1.0)

**全部为虚构测试资料，不能用于真实贸易、报关或法律合规证明。**

## 统一场景
- 货物编号：`LCAI-UAT-001`
- 路线：中国 → 德国
- 产品：Rechargeable Bluetooth Speaker / NOVA-BS20
- 发票：1000 PCS × USD 20 = USD 20,000
- 正常装箱单：1000 PCS / 100 cartons / 550 KG net / 620 KG gross
- 冲突装箱单：**900 PCS** / 90 cartons（专门制造数量不一致）
- HS 8518.21 **仅为示例，不代表准确税则归类**。

## 文件与测试目的
| 文件 | 用途 | 预期 |
|---|---|---|
| `01_Commercial_Invoice_1000PCS.pdf` | 文本 PDF 提取 | 提取发票号、1000 PCS、USD 20,000 |
| `02_Packing_List_1000PCS.pdf` | 正常跨单证核验 | 与发票数量一致 |
| `03_Packing_List_CONFLICT_900PCS.pdf` | 故意制造冲突 | 与发票数量不一致（1000 vs 900） |
| `04_Invoice_OCR_Image.png` | 图片 OCR | 识别与发票相同的信息 |
| `05_Invoice_Scanned_ImageOnly.pdf` | 扫描 PDF OCR | PDF 内无可提取文本，应走视觉 OCR |
| `06_Invoice_INVOIC_EDIFACT.edi` | 结构化 EDI 解析 | QTY 1000, PRI 20, MOA 20000 |
| `07_EU_Declaration_of_Conformity.pdf` | 合规预检的证据缺口 | 不能将供应商自述当成官方认证 |

## 推荐演示路线（不要把正常与冲突装箱单同时当作有效文件）
1. 新建货物，填写 `LCAI-UAT-001`。
2. 上传 `01` + `02`：检查文本 PDF 解析、来源证据和数量一致性。
3. **替换** `02` 为 `03`：检查 1000 vs 900 的数量冲突。若系统不支持替换，另建测试货物进行冲突测试。
4. 展开异常，查看来源；人工处理后重新核验，验证状态和审计记录。
5. 新建独立 OCR 测试货物，分别上传 `04` 和 `05`，检查视觉识别和页码引用。
6. 新建独立 EDI 测试货物，上传 `06`，验证确定性结构化解析。
7. 上传 `07` 观察合规风险或材料缺失提示；**具体触发规则依系统实现而定，不能预设一定触发**。

## 重要说明
- `04` 与 `05` 是 `01` 的同一内容的不同载体，**不应当作三笔不同的真实发票**。
- 测试字段提取时请以 `ground_truth.json` 为人工对照；对于不同格式，字段命名可能不同。
- 若系统只支持特定扩展名，先确认 EDI 文件格式白名单。
- OCR 结果依模型而异，不能预先保证全部字段识别正确。
- 对错误场景测试请优先使用独立货物，以免污染最终录屏数据。
- 录屏展示时建议保留页面中的 `SYNTHETIC TEST DOCUMENT` 标记。
